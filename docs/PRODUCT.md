# 海风 · 把今天的一小片，带回来

日期：2026-09-23。状态：总控依据用户自主推进授权选定的第一版假设，尚未验证用户需求。

## 产品判断
Reachy 的表情和身体是一种交互媒介，不能替代明确用途。海风聚焦随时可做的一次桌边回顾：挑一张照片，说一句为什么想留下它，机器人围绕真实细节回应，片段被保存并可回看。不声称已形成每日习惯，不做打卡或自动提醒。

核心用户暂定为愿意记录生活、但不想认真写日记的人。该人群是待验证假设，不宣称市场需求已经成立。

## 比较过的方向
| 方向 | 收益 | 代价 | 决策 |
|---|---|---|---|
| 即时看图问答 | 复用最多，最短路径跑通硬件 | 与手机视觉助手差异小 | 作为底层能力 |
| 生活片段的桌边回顾 | 眼镜提供真实视角，机器人提供听众，留下可回看的内容 | 需要片段历史、克制的对话和真实播报 | 第一版 |
| 远程共享第一视角 | 机器人可能成为远方人的在场载体 | 多端授权、网络与实时链路复杂，当前无需求证据 | 延后 |

## 第一版流程
1. 打开本机页面，一次性配置实际模型服务；密钥只留本机。
2. 新建片段，上传照片或主动触发眼镜拍照。无眼镜也可上传；绝不静默改用机器人摄像头。
3. 照片预览显示真实来源与时间。写一句话，发送。允许纯文字，界面明确当前是否沿用照片。
4. 海风结合真实图像和用户说的话作简短回应，最多一个自然追问。机器人动作、音频、文字独立显示状态。
5. 会话自动保存在本机。侧栏按片段回看原照片和对话；不自动生成虚假的生活记录。
6. 停止确实取消后续模型/设备操作。重新开始创建新片段，不删除旧记录。

## 气质与表达
安静、具体、有好奇心、有边界。暖白底、深绿字、少量赭橘，照片是中心，像一页展开的手账。中文正文用系统无衬线，主标题可用宋体。无假在线、假回复、占位记忆、亲密关系承诺或心理诊断。

首页：海风 / 把今天的一小片，带回来。空状态：今天，有什么想留下？主操作：放一张照片、用眼镜拍一张、写给海风。第一版输入是打字，输出可由Reachy朗读；不暗示已经实现语音输入。已有图片时提示“这次沿用这张照片”。设备配置收在设置，不让用户处理 request_id 等实现字段。

## 技术边界
Windows 单用户本机服务，同源 UI、SQLite、单设备串行 worker。照片和密钥不上传 Git。模型必须真实配置且支持图片；无模型时明确提示，照片仍能保存。机器人只做受限的小幅触角反馈。声音必须选中 Reachy 输出设备，不能默认电脑扬声器。电脑听得到或 API 接受请求都不代表真机可闻验收通过。

BLE 仍受电脑覆盖范围限制；本版不承诺离线外出眼镜采集、高清相册同步、连续语音、手机原生 App、多用户和公网部署。手机仅做响应式页面及可信局域网访问路径。眼镜入口明确为页面按钮触发，通过电脑 BLE AA13 写入拍照指令，AA15 收取完整 JPEG；上游 E06 样例为368×480小图，本机以解码结果为准。失败不自动换来源。此次不会实现“在外拍完、回家自动同步”。

照片保留在本机直到用户删除片段；删除入口同时移除关联图片和对话。发送前说明文字和照片将交给配置的模型服务；本地保存并不意味着模型推理离线。

BLE实现合同：AA15使用52 58帧头与58 52帧尾、BE长度和加和校验；0x97声明总长，0x98携带字节偏移，0x99结束；只有覆盖全部字节且JPEG可解码才完成。限制单帧4KiB、文件16MiB，5秒无进展失败，重复片段不能虚增完成度，取消/超时断开连接。固定上游源码为依据，合成碎片/乱序/损坏测试通过，Python后备路径仍待本机真机验证。

## 验收
自动测试覆盖鉴权、图片归属、取消、串行、幂等、重启中断；页面实测上传/发送/停止/历史恢复/设置，桌面1400与手机390截图检查。硬件逐段记录真实照片、运动完成、输出路由和可闻状态。20轮测试明确是模拟还是实机。未满足的硬件环节保留阻塞，不能用测试替身宣称完整交付。

## 分发与下一步
私有 GitHub 源码、Windows 一键启动、清晰配置和运行日志。当前交付为本机可用应用；打包安装器和公开商店发布延后。总控完成实现与实机验收后，真实体验检验是：能否在两分钟内留下一个愿意再次打开的生活片段。

## 产品试验与证伪
独立审阅指出眼镜与机器人目前仍有可替代性，这是明确保留的产品风险。先验证桌边表达是否成立，不把硬件必需性写成结论。后续邀请5–8位实际目标用户各尝试3次（本次未招募、未联系他人）：记录两分钟完成率、自主再次打开率、回应是否打断，以及屏幕文字/机器人表达的差异。若实体表达没有帮助用户讲完或回看，重新选择用途；若眼镜不比上传更便利，保持可选入口，不为硬件强塞流程。
