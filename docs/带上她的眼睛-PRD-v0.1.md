# 《带上她的眼睛》PRD v0.1

日期：2026-09-23。状态：讨论稿；硬件方案待验证，非实现完成声明。

## 1. 产品定位

把家里的 Reachy Mini 带进我的日常视野：我主动用眼镜分享眼前的一刻，她看见后，通过随身硬件给我回应。回到家，我们还能接着这段共同经历说话。

核心用户：已经与家中 Reachy Mini 建立陪伴关系、希望外出时也能分享生活的人。首轮以真实使用者的体验验证为主，暂不推断市场规模。

核心价值：分享发生的当下，感到自己的分享被一个熟悉的伙伴接住。识别照片是能力，主动分享与有依据的回应是体验中心。

正式产品名为《带上她的眼睛》。沿用当前 D:\海风 私有仓库与可复用代码；旧 docs/PRODUCT.md 是此前桌边回顾原型的记录，其“外出共享延后”不再代表本轮产品目标。程序和设备名称暂不批量改动。

## 3. 核心场景：今晚的月亮

1. 我看见月亮，想让她也看见。用手按下眼镜腿上的实体按键拍照，不必先打字或说话，也不操作 M5 发起拍摄。
2. 随身端确认这张照片已取到，显示简短发送状态。尚未送达时不说“她看到了”。
3. 同一个陪伴服务收到照片，理解可见细节，生成一次回应。
4. M5Stack 用一个短表情和一句短话回应；有震动能力时，以短促触感提醒我回应已到。
5. 我可以看一眼、轻按表示收到，或者什么都不做，继续看月亮。她不要求接着聊。
6. 回家后主动开启回顾，Reachy Mini 能接续这张照片及当时的回应。

表达示例仅作设计说明，不是固定回复库：若确实可见月亮与云，可以说“月亮从云边露出来了。”若只有模糊亮点，则承认“这张有点暗，还看不清。”不得编造月相、地点、用户心情，也不因为案例叫“月亮”就强行识别为月亮。

## 4. 设备分工与反馈设计

眼镜负责采集第一视角；Reachy Mini 是家中实体；M5Stack 是同一角色随身的回应窗口；陪伴服务统一持有角色、事件和记忆。不得在 M5Stack 上另造一个彼此失忆的宠物。

| 反馈 | 作用 | 取舍与优先级 |
|---|---|---|
| 简短状态图形 | 说明拍摄、发送、等待、失败 | P0；与角色表情区分，不能把联网成功当情感回应 |
| 角色小表情 + 短句 | 既有生命感，又能确认回应针对这一张照片 | 推荐 P0，前提是设备有可读屏幕；单句建议不超过 24 个汉字，可调整 |
| 震动 | 不看屏幕也知道她的回应已到 | 用户明确偏好，优先验证外接马达/触觉模块方案；通过供电、驱动、体积及真实触感验收后纳入 MVP。当前 StickS3 无内置马达，未验证前不承诺可用 |
| 短声音 | 更强的角色感 | P1，主动播放或开启后使用；需要核验扬声器，公共环境默认安静 |
| 长文本/聊天列表 | 承载复杂交流 | 不进入外出主流程，避免随身端变成需要持续操作的聊天屏幕 |

表情与短句必须出自同一次回应。M5Stack 按键短按可重看最近回应；“已收到”仅代表用户读过，不等于同意模型推断。长期偏好不可由一次按键自动确认。按实测 135×240 小屏设计，两至三行短句、不强制滚动；24 字仅为初始上限，最终以中文字体及实体可读性测试调整。

### 震动候选与放行条件

已审阅 [StickS3 外接震动权威报告](https://github.com/kimniniup-creator/reading-pet/blob/6068425bccee72caf908434df36f5e8373b40dfd/docs/hardware/HAPTICS_FEASIBILITY.md)，固定版本 6068425。结论为**有条件可行，列入 MVP 候选，尚未通过实物验收**。推荐首样为 Adafruit DRV2605L #2305、#1201 ERM 马达和独立 3.3V 稳压板；具体接线、电源与驱动参数只由该硬件报告维护，PRD 不复制工程接线表。

产品放行须满足：到货板型与电平核对通过；USB/电池供电及峰值负载正常；无线传输、音频与触觉并行不重启、不阻塞；至少 20 次实际手持/衣袋触感评估与 100 次有间隔事件压力测试通过；携带体积、固定方式和续航可接受。当前不承诺装入原壳。

仅首次实际呈现新回应时轻短震动一次，可关闭；重试传输、重看、重复消息、快照恢复或历史补送不补震。模块故障保持画面与回应可用，明确触觉不可用。关闭期间同样消费本次提醒，不在重新开启后补震，语义沿用最小事件协议。

Seeed Grove-Haptic 仅作备选，线序与 5V 上拉条件不允许直接插接。上述结论不启动采购、接线、驱动开发或刷写；完成实物验证后再将候选改为已验收能力。

## 5. MVP 功能需求

| 编号 | 输入与规则 | 输出与验收 |
|---|---|---|
| F01 主动分享 | 用户手动按眼镜腿上的实体按键拍摄，一次拍摄对应一个事件；系统接收该次按键拍下的新图。M5 不承担拍照触发 | 得到本次完整新图、来源与时间；若现协议无法取得按键照片，记录接入阻塞并解决，不改用 M5 远程拍摄、不复用旧图、不改用机器人摄像头 |
| F02 可信状态 | 区分已拍到、发送中、服务已收到、回应已到、待重试 | 未完成理解前不演出“理解了”；用户能判断等待或失败 |
| F03 图片回应 | 仅以本次图片、已授权记忆与角色设定生成；无需文字补充也能分享 | 一条有依据的简短回应与匹配表情；模糊图不虚构细节 |
| F04 随身输出 | 以实际 M5 能力选择屏幕/触感输出；默认无须手机操作 | 口袋取出或佩戴状态下可感知回应；声音可关闭 |
| F05 身份连续 | 统一角色标识与事件记录，M5 与 Reachy 读取同一事件 | 回家后可正确接续，不能对同一图片产生互相矛盾的记忆 |
| F06 失败恢复 | 断网只在已安全取到图时暂存；重试沿用同一事件 ID；保存拍摄与送达时间 | 不丢已承诺保存的照片，不重复回应；延迟送达有明确标识 |
| F07 家中离线 | 区分“陪伴服务在线”和“Reachy 实体在线” | 建议云端可回应时继续随身体验，实体恢复后同步；该架构选择待确认，不冒充家中实体已执行动作 |
| F08 控制与删除 | 设置中告知图片去向；用户可取消待发送事件、删除片段 | 删除图片、回应与关联派生记忆；跨端离线删除采用墓碑，同步恢复后不复活 |

首次设置可以使用电脑。日常分享不要求手机页面、电脑页面或额外文字输入。MVP 不引入常开录像、持续监听、自动拍摄、情绪诊断、打卡、强制回应或社交发布。

### 旧固件功能收口（用户最新明确指令）

保留 M5 现有角色形象。停用旧心情数值、疲惫、陪读与暂停机制，同时停止相关计时、衰减、提醒和后台状态驱动；不只是隐藏界面。旧状态不得继续改变角色表现、覆盖照片回应或占用分享按键。照片触发的短表情属于本次回应，不恢复旧养成数值。

游戏可以保留，但不属于 MVP，不自动弹出、不驱动旧养成数值，也不阻塞分享与回应。首版要求眼镜腿按键拍照、真实链路状态、针对照片的角色回应，以及失败重试/待发送取消；M5 仅为重看、重试和取消等反馈操作安排按键，不触发拍照。

旧固件停用由唯一固件集成任务执行，本 PRD 任务负责定义与整合，不并行刷写设备。固件总控为 01a0c813，唯一固件集成/COM/烧录负责人为 01a0c5c6；01a0c7df 只负责美术资产。产品定义以 haifeng 为准，固件实现及恢复包以 D:\reading-pet 为准，交叉链接、不双写代码。最新安排为保留形象与历史存档、停掉旧后台业务，游戏源码保留但 MVP 关闭入口；安排不代表刷写验收已完成。

## 6. 实现路径与硬件验证

当前上游提供 Windows 本地桥接：电脑通过 BLE 取得眼镜 AI JPEG，转给视觉模型与 Reachy。上游记录过 E06/S3 的 368×480 图片；这不是本机眼镜或 M5 真机已通过的证据。用户已确认眼镜腿有手动拍照按键；当前本地 Python 实现通过写入命令触发拍照，尚不能证明能够接收实体按键拍下的照片。需要验证该照片的事件通知、获取路径和时序；远程命令拍照不能代替此项验收。

建议分阶段验证，不能用桌面演示代替外出验收：

1. **桌面反馈试验**：电脑收到真实眼镜照片，生成回应，再送往 USB 连接的 M5；验证屏幕/声音/触感是否足以表达“她回应了”。这一阶段需要电脑，不称为可外出产品。
2. **随身链路试验**：核验具体 M5 的 BLE 中央角色、图片内存、Wi-Fi 与 BLE 共存能力。若成立，眼镜 → M5 → 网络 → 陪伴服务 → M5，家中 Reachy 同步事件。模型推理不默认在 M5 上运行。
3. **真实外出验收**：随身电池供电、家中电脑不在蓝牙范围内，完整走通拍摄与回应。按已确认条件，以口袋里的手机提供热点，M5 承担随身采集和反馈的目标路径进行验证；完全不带手机及独立蜂窝网络不进入本轮 MVP。

若 M5 无法稳定接收眼镜图像，则它仍可做反馈端，但需单独的随身采集网关。不得悄悄把手机 App 改成必经入口。家庭服务使用出站连接或受控中继，不直接公开 Reachy 控制端口。

## 7. 气质与记忆规则

参考「屿」：亲近、具体、低压力，有真实依据。小屏以有限色、清楚的表情和短句呈现，不做满屏通知面板。触感、动画都轻而短，强度按实物测试调整。

照片代表“我想与你分享”，不自动代表“我开心/难过/需要安慰”。回复不必每次问问题；长时间没分享不惩罚、不抱怨。模型不可用时诚实显示状态，不能用预制温柔句子假装看懂。

照片与本次回应可以成为事件记录；“用户喜欢月亮”等长期偏好必须独立确认、保留来源且可撤回。不跨项目读取「屿」的私人内容。原图保留期及云服务删除能力在上线前明确；讨论稿不擅自承诺永久存储。

## 8. 验收标准与成功指标

以下是待测目标，不是现状性能：

- 真实按下眼镜腿按键后，记录拍摄到系统收到事件/新图的耗时；M5 收到可核验事件后 1 秒内给出对应状态，不在尚未收到事件时假装已受理。“已拍到”必须等完整照片实际到达。
- 外接震动方案通过后，真实回应到达触发一次轻短震动，可关闭；在实际佩戴/口袋放置状态确认能感知，且不因重连重复震动。震动不代替短句的内容表达，也不由上传成功提前触发。
- 指定联网条件下，从完整图片取到至随身回应的 P95 目标 ≤10 秒；10 秒以上持续明确等待，30 秒进入超时/可重试状态。端到端总耗时另行记录，不隐去拍照传输时间。
- 完成 20 次真实外出分享，至少 19 次无须掏手机或操作电脑即可得到对应反馈；全部记录图像来源、时间及硬件实测结果。
- 包含白天物体、夜空/月亮、模糊图、断网重连、重复按键、Reachy 离线六类用例；任何用例不得假成功、串图或重复播报。
- 月亮实测必须检查照片是否足以支撑识别；若不行，调整光学/输入方案或如实缩小承诺，不能让模型按提示猜答案。
- 至少做 3 次真实散步体验，记录回应是否打断看风景、用户能否区分收件与理解、以及是否愿意再次主动分享。此项验证产品价值，不预先声称成立。
- 回家后能找到同一片段并接续；删除后在线与后续重连的设备均不再引用它。

## 9. 当前待决策

1. 型号已确认为 M5StickS3，语音可闻由固件总控转达用户确认；继续验证新照片回应的中文实体可读性、实际提示音体验、电池续航，以及佩戴或口袋使用方式。
2. 手机仅作热点已确认；仍需实测 M5 同时完成眼镜 BLE 采集和 Wi-Fi 上行，不能拿热点替代缺失的采集能力。
3. 眼镜腿实体按键是已确认拍照入口；待验证其照片能否被现协议主动推送或拉取，不保留 M5 按键拍照替代方案。
4. 外出时允许陪伴服务独立于家中 Reachy 在线与否运行，还是要求家中实体收到后才算送达。
5. 优先验证 StickS3 外接震动模块的驱动、供电、体积、续航和真实触感；可行则纳入 MVP，不因板载无马达直接放弃该偏好。
